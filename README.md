# Бот записи к мастеру маникюра

Telegram-бот для онлайн-записи клиентов. Один и тот же код подходит разным мастерам: имя, услуги, цены, расписание и адрес хранятся в PostgreSQL, а не в Python-файлах.

Клиент нажимает кнопки (услуги → дата → время → подтверждение). Искусственный интеллект не используется.

## Что умеет бот

- запись клиента с защитой от пересечения слотов
- просмотр и отмена своей записи
- информация о мастере из базы
- админ-панель: записи, услуги, расписание, закрытые даты, клиенты, настройки мастера

## Структура проекта

```
app/
  main.py              запуск бота
  config.py            настройки из .env
  bootstrap.py         создание первого мастера
  handlers/            команды и кнопки Telegram
  keyboards/           клавиатуры
  services/            бизнес-логика (слоты, записи)
  repositories/        запросы к базе
  database/models/     таблицы
  states/              FSM (многошаговые сценарии)
alembic/               миграции базы
tests/                 pytest
```

Handlers не ходят в SQL напрямую для сложной логики: они вызывают services, те — repositories.

## 1. Установка Python-зависимостей

Нужен Python 3.12 или новее.

```bash
cd nailsbot
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Linux / macOS:

```bash
source .venv/bin/activate
pip install -r requirements.txt
```

## 2. PostgreSQL

Создайте базу, например `nailsbot`.

```sql
CREATE DATABASE nailsbot;
```

Пользователь должен иметь право создавать расширения: бот использует `btree_gist` для защиты от двойной записи.

## 3. Файл .env

Скопируйте пример и заполните свои значения:

```bash
copy .env.example .env
```

Содержимое:

```
BOT_TOKEN=токен_от_BotFather
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@localhost:5432/nailsbot
ADMIN_ID=ваш_telegram_id
MASTER_ID=
```

Как получить значения:

- `BOT_TOKEN` — создайте бота в [@BotFather](https://t.me/BotFather)
- `ADMIN_ID` — напишите [@userinfobot](https://t.me/userinfobot)
- `DATABASE_URL` — логин, пароль, хост и имя базы
- `MASTER_ID` — оставьте пустым, если мастер один. Если в базе несколько мастеров, укажите id нужного

Пароли и токены в код не записывайте. Файл `.env` в git не попадает.

## 4. Миграции

Примените схему базы:

```bash
alembic upgrade head
```

Если ошибка про расширение `btree_gist`, выполните от суперпользователя PostgreSQL:

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;
```

и снова `alembic upgrade head`.

## 5. Первый мастер

```bash
python -m app.bootstrap
```

Скрипт создаст мастера-заготовку и расписание (пн–сб 10:00–20:00, вс выходной). Имя «Мастер» — заглушка, его нужно заменить в боте.

## 6. Запуск бота

```bash
python -m app.main
```

Откройте бота в Telegram и отправьте `/start`.

## 7. Настройка через Telegram

Напишите боту `/admin` с аккаунта, чей id указан в `ADMIN_ID`.

1. **Настройки мастера** — имя, описание, контакт, адрес, часовой пояс (`Europe/Moscow`)
2. **Услуги** — добавить услугу (название, минуты, цена в рублях)
3. **Расписание** — рабочий/выходной и часы вида `10:00-20:00`
4. **Закрытые даты** — разовые выходные, клиенты на них записаться не смогут

Цены хранятся как `NUMERIC` (десятичное число), не `float`.

## 8. Тесты

```bash
pytest
```

Проверяются слоты, пересечения записей, отмена, рабочие часы, закрытые даты, неактивные услуги и разделение данных по `master_id`.

## Несколько мастеров

Таблицы услуг, записей, расписания и выходных всегда привязаны к `master_id`. Второй мастер — это новая строка в `masters` и свой `MASTER_ID` в `.env`, без копирования проекта и без правок Python.

Регистрация мастеров, оплата подписок и личный кабинет в этом MVP не делались.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | клиент | главное меню |
| `/admin` | администратор | панель мастера |
| `/cancel` | любой | сбросить текущий шаг |
